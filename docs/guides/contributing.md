# Contributing

## Pull Request Description

Every PR description follows four sections. Keep each section short — the goal is a reviewer who can assess the change in under two minutes.

**Overview** — one or two sentences saying what changed and what it affects. No background, no motivation yet.

**Why** — the reason behind the changes. State the problem, constraint, or decision that made the change necessary. This is the section that prevents the same discussion from happening again in six months.

**How** — the approach and trade-offs, not a line-by-line walkthrough. Explain the ideas so a reviewer can evaluate whether the approach is sound before reading the diff.

**Checklist** — the steps a reviewer must complete to accept the change. Write these as concrete actions ("verify X still passes", "confirm Y field appears in the event"), not vague sign-offs.

The PR template at `.github/pull_request_template.md` pre-fills this structure.
